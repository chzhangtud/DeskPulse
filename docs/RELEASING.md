# Release checklist

Release work must use an isolated checkout/export and fresh output folders. Do not publish from an installation that contains private pairing state, or overwrite running Windows/Linux binaries.

1. Update `<Version>` in `collector/DeskPulse.Collector.csproj`, Android `versionName` and increment `versionCode`. Update README download URLs, runbook examples and the Linux archive path in CI/AGENTS. Keep existing release tags and their assets intact. Keep the Android signing key unchanged for in-place preview upgrades; never commit a signing key.
2. Choose a supported .NET 8 runtime patch from [Microsoft's release metadata](https://builds.dotnet.microsoft.com/dotnet/release-metadata/8.0/releases.json). For v0.2.0 this is 8.0.32. Use `scripts/Build.ps1 -RuntimeVersion 8.0.32` for Android/Windows and `DESKPULSE_RUNTIME_VERSION=8.0.32 bash scripts/linux/build.sh` on Linux. `bash scripts/linux/build.sh linux-arm64` cross-publishes ARM64; a cross-build does not prove ARM64 runtime behavior.
3. Run the commands in [AGENTS.md](../AGENTS.md), including Node, collector fixtures/integration, Android assemble/lint, Linux helper/package checks, and a real isolated user service test when possible. Extract and test the actual Windows and Linux x64 archives using `DESKPULSE_COLLECTOR` to select their executable. Verify runtimeconfig lists the selected runtime patch. Verify Android APK version/code/signature and signing continuity with the previous APK. Report the absence of physical-phone/ARM64 tests honestly.
4. Inspect final archives: complete runtime files and licenses, normalized Linux owners/executable modes, both Linux guides with working links, no state, pairing strings, certificates, clients, logs, PDBs or personal build paths. Run `tests/linux_package_test.py` on both architectures. Retain original third-party notices. APK development signing and Windows lack of Authenticode signing must remain explicit in preview notes.
5. Create `SHA256SUMS.txt` with SHA-256 hashes of the four binary assets, named exactly as in the READMEs. Include `LICENSE` as a separate release asset. Review staged changes and commit without including local plans or private build evidence. Push only when the user explicitly requested it; wait for the matching Ubuntu and Windows CI run to pass.
6. Create a draft release at the reviewed commit and a new version tag. Upload the APK, Windows x64 ZIP, Linux x64/ARM64 tarballs, checksum manifest and license. Compare the GitHub asset sizes and SHA-256 digests against local files. Publish the preview only once all assets and checks pass. Never replace published assets silently; use a new version to correct them.
7. Re-fetch the published release to check its tag/commit, asset names, canonical download URLs and digests. Check both READMEs point to the actual assets. Keep older releases available. Release validation reports must distinguish native Linux CI, WSL runtime tests, cross-build-only architectures and physical device testing.

Linux runtime dependencies, service management, private state migration and rollback are documented in [English](LINUX.md) and [简体中文](LINUX.zh-CN.md). The self-contained runtime is patched by replacing the DeskPulse package, independently of system .NET updates.
